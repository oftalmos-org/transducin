Quickstart

Clone & configure

Create a .env file with your Orthanc connection and optional Graefe webhook.

git clone https://github.com/oftalmos-org/transducin.git
cd transducin
cp .env.example .env
# Edit .env: set ORTHANC_HOST, ORTHANC_HTTP_PASS, GRAEFE_WEBHOOK_URL

Start with Docker Compose

Spins up Transducin API + hot-folder watcher. Orthanc is assumed to be running separately.

docker compose up -d

Drop an OCT file

Copy any .opt or .EX.DCM file into the watched input folder. Transducin detects it, extracts measurements, generates a DICOM SR, and stores it in Orthanc.

cp my_scan.opt /path/to/transducin/input/

Open the dashboard

Visit http://localhost:8004 to confirm the study was processed and query patient measurements.

Architecture

Transducin is a single Python service with three components: a hot-folder watcher, a conversion pipeline, and a REST API.

.opt / .EX.DCM → HotFolderWatcher → DeviceAdapter → OCTClinicalData ↓ SRBuilder (TID 1500) ↓ Orthanc C-STORE + Graefe webhook REST API (port 8004): GET /health → pipeline + Orthanc status GET /stats → aggregate counts (no PHI) GET /patients/{noel_id}/oct-latest → most recent SR measurements GET /patients/{noel_id}/oct-trend → last 5 studies, chronological GET /patients/{noel_id}/oct-latest/bscan → central B-scan (JPEG, proxied from Orthanc) GET /patients/{noel_id}/oct-latest/slo → SLO en-face image (JPEG) GET /patients/{noel_id}/oct-latest/etdrs-overlay → ETDRS 9-sector grid PNG (generated) GET /patients/{noel_id}/oct-latest/rnfl-bullseye → RNFL bull's-eye PNG (generated) POST /store-summary → pgvector embedding store POST /refraction → refraction DICOM SR builder

NOEL patient ID protocol

All DICOM instances use a privacy-preserving patient identifier derived deterministically from demographics: NOEL_ID = apellido_paterno[:2] + apellido_materno[0] + nombre[0] + YYYYMMDD. No full names are stored in DICOM tags.
